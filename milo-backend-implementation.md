## Decisions made without asking

Each is a default chosen to keep moving; all are cheap to revisit unless marked otherwise.

1. **Service language stays TypeScript (Node), not Python — for now.** The working prototype, the Rust bridge and all salvage material are TypeScript, so repurposing is direct translation with no cross-language rewrite. The plan already says the language "remains a design choice", and the versioned socket protocol means a Python (or Rust) service can replace this later without changing clients. *Cost of reversing:* moderate; the protocol and tests are the contract.
2. **Zero npm dependencies in `milo-service`.** It must eventually ship as a signed bundled helper; every dependency is packaging, licensing and supply-chain weight. Consequences: SQLite via built-in `node:sqlite`, and a small in-house cron evaluator instead of Aiden's `croner` dependency.
3. **Minimum Node raised to 22.13** (built-in `node:sqlite` without a flag). Still run with `--experimental-strip-types` for older 22.x/23.x; Node 25 is used locally.
4. **SQLite replaces `tasks.json`.** The plan calls for "SQLite jobs, schedules, events, recovery"; JSON-with-rename cannot give multi-table transactions. WAL mode, `synchronous=FULL`. An existing `tasks.json` is validated, imported once and renamed to `tasks.json.imported`; a corrupt one still aborts startup without being touched (prototype behavior kept).
5. **Single-writer ownership instead of leases/fencing.** Aiden's job engine uses leases because multiple workers compete. Milo has one service process guarded by the existing lock file, so an attempt is owned by the process that holds the lock. Attempts are still recorded (number, start/end, outcome) so leases can be added if a multi-worker design appears.
6. **Crash recovery resumes automatically when it is provably safe.** A task found `running` after a crash: every `intended` (not yet confirmed) effect is reconciled. Filesystem writes compare the file's SHA-256 with the intended content (Aiden's reconciler). Occurred → recorded as applied and the result is appended; did not occur → recorded as not applied and the tool call is reported to the model as not executed; anything unknown → task becomes `needs_review` and is not retried. With no unresolved effects the task is requeued from its persisted message log, at most 3 crash recoveries before it is marked `failed`. Read-only tool calls are safe to repeat. This is the "Level 3 recovers from failures" behavior while never blindly repeating an uncertain external effect.
7. **Default-deny permissions.** The app's Permissions screen already promises "Nothing is enabled by default", so: no file roots, network off, shell off. Tools that lack permission return a structured `permission_denied` result the model can explain. Memory tools are internal and always available.
8. **Approval policy.** Read-only tools inside granted scope run without prompting. `file_write` asks unless the user turns on `autoApproveFileWrites`. `shell_run` (when enabled) runs provably read-only commands (Aiden's `isReadOnlyCommand`) without asking; everything else asks; `dangerous` commands always ask and can never be auto-approved by a setting (AGENTS.md contract). Content flagged by the secret/terminal-injection scanner forces a prompt. Approvals are per tool call ("once") and bound to an argument digest, so an approval cannot be replayed onto different arguments. Session/permanent grants are deferred.
9. **Approval waits park the task, not the worker.** The task moves to `waiting_approval` and releases the worker; approving executes that exact recorded call and requeues; denying appends a "denied by user" tool result and requeues so the model can adapt.
10. **One worker, one task at a time.** A single local model is the bottleneck; concurrency would only contend for it. Foreground priority, batching and shared execution are later inference-layer work (per the plan).
11. **Step cap 24 per task** (Aiden: 90). Small local models loop more; 24 bounds runaway cost. Configurable via `settings`.
12. **Protocol v2 with a per-start auth token.** The service writes a random 256-bit token to `auth.token` (0600) at startup; every request carries `auth`. Same-user processes can read the file, so this is not app attestation, but it stops blind connections, makes tokens rotate on restart and gives a place to add stronger client authentication. `hello` negotiates the version; unsupported versions get a clear error. `events.subscribe` turns a connection into a stream for live UI updates; one-shot polling with `events.list` (`after` cursor) also works.
13. **Inference: mock by default, local OpenAI-compatible backend opt-in, cloud opt-in behind a second switch.** The mock is deterministic and plainly labeled; it understands `/tool <name> <json>` lines in a goal so tests and the UI can drive real tool, approval and recovery paths without a model. The OpenAI-compatible adapter targets Ollama / llama.cpp `llama-server`; a non-loopback URL is refused unless `allowRemote` is set. API keys are read only from the environment (`MILO_INFERENCE_API_KEY`), never stored in SQLite. The router has an `engine` slot that will hold the custom inference engine behind the same `InferenceBackend` interface.
14. **Ported a compact chat-completions adapter rather than Aiden's 1,428-line one.** Aiden's handles many vendors' quirks Milo does not target. The port keeps the behaviors that matter: message/tool mapping, tool-call argument JSON validation, finish-reason mapping, usage, cancellation, bounded responses.
15. **Small reviewed tool set** (seven tools). The plan says "start with a small reviewed tool set". Browser, MCP, plugins, coding, subagents and channels stay as Aiden references.
16. **File tools resolve real paths** and must stay inside a granted root after symlink resolution; writes to `.ssh`, `.gnupg`, keychains and Milo's own service directory are refused even inside a root. Output is bounded (256 KiB read, 16 KiB returned to the model per result).
17. **SSRF guard improvements over Aiden:** also blocks `0.0.0.0/8`, IPv4-mapped IPv6 (`::ffff:127.0.0.1`), multicast/reserved ranges, and re-checks every redirect hop (manual redirect following, max 5).
18. **Memory provenance enforced by origin:** entries added by the user through the protocol are `said`; the model may only write `saw` or `guess` and can never overwrite a higher-trust entry (Aiden's `canOverwrite`). Prompt injection is bounded per namespace (Aiden's char limits) and labeled as non-authoritative data.
19. **Scheduler semantics:** misfire policy `run_once` by default (one catch-up run after wake if the latest missed instant is under 24 h old; chosen over Aiden's `skip` because a laptop asleep at 9:00 should still produce the 9:00 summary once it wakes), `skip` (runs only within 60 s grace) or `catch_up` (up to N). Overlap policy `skip` by default: an occurrence whose previous task is still active is recorded as `skipped_overlap`. Occurrence keys (SHA-256 of schedule id, revision, instant) are unique in SQLite so a restart or duplicate scan cannot create a second task for the same instant. Missed schedules are evaluated on startup and every 15 s, which covers sleep/wake. In a DST fall-back hour a wall-clock time fires once, not twice; nonexistent spring-forward times are skipped.
20. **Unit tests as `.test.ts` under `milo-service/test/`** run by `node --test`; the original end-to-end tests were rewritten for protocol v2 rather than kept on v1.
21. **No changes to the Aiden tree.** Nothing under `core/`, `moat/`, `providers/` etc. was edited or deleted; ported files carry an AGPL provenance header naming their source (license decision still open per the plan).
22. **Frontend bindings only, minimal UI.** The request was backend. Rust commands and TS bindings were added for everything; the existing views keep working with the new task statuses.

23. **CLI is a thin second client** (`milo-service/cli.ts`, `bin/milo`): every command is one protocol call against the same service, task store and approvals as the app; `--json` on everything. `milo ask` follows the task and prompts for approvals when attached to a terminal.
24. **Login lifecycle via a dev LaunchAgent** (`milo service install|uninstall|status`, label `com.areendabadghav.milo.service`, matching the app identifier): starts at login, restarts after crashes, keeps data on uninstall. I did not install it on this Mac; that is persistent system state and is your call. Release builds should register a signed helper through `SMAppService` instead.
25. **Text-format tool calls are accepted from local models**, only for tool names offered in that request. Found with a real model: `qwen2.5-coder:7b` via Ollama returns calls as JSON text (bare, fenced, JSON-lines, or in `<tool_call>`/`<tool_request>` tags) instead of structured `tool_calls`. Ported from Aiden `localPromptToolsAdapter.ts`.
26. **Side effects must be grounded.** Also found with the real model: it batched `file_read` + `file_write` in one step and guessed the content ("John Doe") before seeing the file. `file_write` and `shell_run` are now refused with a `deferred` result when planned alongside earlier calls whose results the model has not seen; it re-issues them next step. Repeats of already-observed calls don't trigger deferral. Deterministic runtime check, consistent with "the runtime owns validation; the model proposes".
27. **Approval prompts preview write content** (first 120 characters), except when the scanner flags it, so a wrong value can be caught before it lands.

## Decisions from the second pass (see milo-backend-remaining.md)

28. **Streamed tokens are live-only events.** `task.delta` is pushed to subscribers but never stored (`seq: 0`, `transient: true`); the persisted assistant message stays the source of truth, so a reconnecting client reads the finished text rather than replaying tokens. Text that starts like a tool call (JSON, code fence, tag) is not streamed, since it would flash raw JSON in the chat.
29. **Context compaction is deterministic elision, not summarization.** With one small local model, summarizing would cost an extra full generation per step. Older tool results are replaced in the prompt with a note telling the model to re-run the tool; the stored log is untouched; the latest step is never elided. Default context 8192 tokens, estimated at 2.5 ASCII characters per token with non-ASCII counted as one token per UTF-8 byte (deliberately pessimistic). If it still doesn't fit, the task fails with that reason rather than letting the server silently truncate.
30. **Usage is recorded per step**, per task and per attempt. When a backend reports no usage, an estimate is stored and flagged `estimated`, so totals are never silently zero.
31. **web_fetch pins the connection** by validating addresses inside the socket's DNS lookup, instead of a separate pre-check alone. Keep-alive pooling is disabled (`agent: false`) so a connection can't be reused across a check boundary.
32. **Task-scoped approvals cover file writes to one resolved target in one task**. Each later call is reassessed; flagged content and dangerous actions still require individual approval. Earlier tool-wide grants are not carried forward. A changed resolved target invalidates a pending approval.
33. **Pause acts at step boundaries.** A model call already in flight finishes and is saved; the task then returns to the queue. Pause is persisted, so it survives restarts and login. Schedules keep recording occurrences while paused (with overlap skip limiting the backlog to one per schedule).
34. **The honesty check annotates rather than rewrites.** Aiden rewrote claims. Milo appends a visible "Milo check" note and emits `honesty.finding`, because rewriting a small model's answer with another heuristic could introduce new errors. Hedged or negated sentences ("could not create…") are ignored.

35. **Goals are context, not authority.** A goal groups tasks and schedules and puts its description, notes and the last five outcomes into linked tasks' prompts (labeled as data). It grants no permissions. Pausing, achieving or archiving a goal disables its schedules, and new work can only link to an active goal.

## Bugs found and fixed during the work

- Events emitted inside a transaction were persisted but never pushed to subscribers, and events from rolled-back transactions would have been pushed. `tx()` now flushes only after commit and discards on rollback (caught by the event-subscription e2e test).
- CLI value flags (`--tz`) leaked into positional text (the schedule goal). Flags are now parsed first; regression test added.
- HTML entity decoding decoded `&amp;` first, double-decoding `&amp;lt;`.

## Subsequent decisions

- The app exposes goal, schedule and memory management through the existing authenticated protocol. Goal status changes warn that linked schedules are disabled, and uncertain-effect review describes the possibility of another action on resume.
- Installed skills are read on demand as untrusted reference content; they do not bypass tool permissions. Skill names are restricted, files are bounded, and symlinked entries are rejected. At this point automated proposals and acceptance remained unimplemented; the following decision supersedes that status.

- Skill candidates use a deterministic summary of successful tool names only, avoiding copied task content, tool arguments or results. A user accepts or rejects the candidate in the app; accepted references remain untrusted and subject to normal policy.

- The desktop starts the service when needed. Stop is offered only for a process started by that app instance; an independently managed login agent remains under its original supervisor. The service can continue when the app exits.
- The macOS package builds a native Node SEA sidecar, smoke-tests its authenticated socket, and signs the bundle ad hoc. Node 25.5+ is required to build it; a standalone official Node binary can be selected with `MILO_SEA_NODE` if a system Node cannot produce a SEA. This is not Developer ID signing or notarization.
- Notifications require explicit macOS authorization requested by the bundled helper and a persisted service opt-in. Committed completion and approval events cause generic notifications from the service even with the app closed; delivery failures are recorded. The unbundled development service reports notifications unavailable. Actual macOS authorization and delivery still need user-driven verification.

- Streaming events are forwarded to the app as transient drafts. Potential structured-call markers after a prose prefix suppress the remaining live text; the stored final response remains authoritative. File creation without overwrite uses an atomic link, avoiding replacement if another process creates the target after the initial check.
- Web fetch has a single 20-second deadline including DNS and redirect handling, and rejects additional IPv6 transition and site-local ranges. Local inference resolves the literal name `localhost` to `127.0.0.1` rather than trusting hosts/DNS; IPv6-only servers must be configured with `::1`, and HTTPS certificates must match the configured numeric address. Inference base URLs reject embedded credentials, queries and fragments.
- A paused, achieved or archived goal cannot have a linked schedule re-enabled; an inconsistent enabled row is disabled by the next scan. Interval misfires are computed arithmetically, and long cron outages find the latest eligible occurrence after the bounded enumeration limit. When the cron scan cap prevents an exact missed count, the event marks it as a lower bound.
- Inference and agent settings are saved atomically. The app's Settings view exposes the existing router and explicitly identifies remote inference as sending task data to the selected server.
- An agent-created `saw` memory must match text in an earlier successful, model-visible tool result; memory and skill tools cannot be used to promote their own lower-trust content to observed evidence. A memory write planned before earlier results are visible is deferred. This is a conservative text-evidence check, not proof that the source itself is accurate.
- Context fitting still uses an estimate rather than the target model's tokenizer. The estimate now budgets non-ASCII UTF-8 bytes more conservatively to reduce undercounting for multilingual text; exact model-specific token accounting remains engine work.
- Event subscriptions replay a stable snapshot in bounded pages before forwarding buffered live events; slow consumers are disconnected rather than given reordered or silently missing history. The CLI displays transient text as a draft only on a terminal, and its request client rejects malformed or incomplete replies.
- Task lists return the newest bounded window in chronological order and combine goal and status filters; the app can load older records with a stable task cursor.


## Decisions from the remaining-work pass

36. **Streaming `timeoutMs` is now an idle limit, with a separate hard ceiling.** For streamed inference, `timeoutMs` is the longest allowed silence: from sending the request to the first byte, and between byte chunks afterwards (it covers slow prompt processing as well as a stalled stream). A long but healthy generation is no longer cut off for its length or retried as a timeout. A second timer bounds the whole stream at `max(600000 ms, 10 x timeoutMs)` (optional `streamCeilingMs` on the backend, used by tests), so a server that trickles bytes forever still ends. Both failures are `TimeoutError` (retryable, like before) with distinct messages ("silent for N ms" / "exceeded the N ms ceiling"). The idle timer is paused while the consumer handles a yielded delta, so a slow consumer is never mistaken for a silent server. User cancellation still reports `Cancelled`. Non-streaming calls are unchanged: a non-stream reply carries no bytes until it is complete, so silence and total time are the same thing and `timeoutMs` stays a total deadline. For users: long local generations stop timing out as long as tokens keep arriving; a genuinely stuck server is detected after `timeoutMs` of silence (default 120 s).
37. **Prompt compaction gains a last step: eliding older tool-call arguments.** After older tool results are elided and older assistant text shortened, `fitContext` replaces the arguments of older tool calls (serialized size of 400 characters or more) with `{ elided: true, note }`, where the note names the tool and the number of characters removed. The call id and tool name are kept so each tool result still pairs with its call. Calls are processed oldest first and the pass stops as soon as the prompt fits. The latest assistant message and everything after it, the system prompt and the goal are never touched, and the stored message log is never modified (prompt-only, as before). If the prompt still does not fit, the task fails honestly as before. For users: a task that wrote several large files can now continue instead of failing; the model sees that older arguments were removed and can re-read the files if it needs them.
38. **`context.compacted` is emitted only when the set of compacted messages changes.** Compaction is still recomputed every step, but the event is stored only when its `signature` (which message indexes were elided as results, shortened as replies, and had arguments elided) differs from the signature in the task's most recent `context.compacted` event. The token estimate is deliberately not compared, since it changes every step. The previous signature is read from the stored events, so the behaviour survives restarts and resumes (events from before this change have no signature and cause one extra event). The event also carries a new `elidedArguments` count. For users: the event log shows when the amount or position of elision changes rather than one entry per step.
39. **Pause is checked before each tool call, not once per step.** The agent loop checks the pause flag at the top of the step and again immediately before each unresolved tool call is resolved. A pause that arrives while call 1 of 3 is running therefore stops calls 2 and 3 from starting; a tool that has already started is never interrupted. Nothing extra needs saving: answered calls already have tool-result messages, and the unanswered ones are recomputed from the stored log when the task resumes, so each call runs exactly once. The task returns to `queued` with a `task.paused` event, as before.
40. **A stream that hits the hard ceiling is not retried.** `InferenceError` gains an optional `retryable` flag (default: decided by error class). Ceiling expiry is still a `TimeoutError` but is marked `retryable: false` with the message "Inference stream exceeded the maximum duration (N ms ceiling); not retried", and the agent's retry check honours the flag, so the attempt fails immediately instead of costing up to three times the ceiling. Idle timeouts ("silent for N ms") stay retryable. This refines entry 36, which called both failures retryable.
41. **Goals view ignores stale task loads and shows failures.** The open goal id and a request counter are held in refs; a `getGoal` response (from opening a goal or from a refresh) is applied only if it is still the latest request for the goal that is currently open, so a late response can no longer show another goal's tasks. If loading fails, the panel shows "Could not load tasks." instead of "Loading tasks…" (which now only appears while a request is pending), and the error message stays visible. Refresh also reads the open goal from the ref, avoiding a stale closure.
42. **Schedule form drops a linked goal that is no longer offered.** After each refresh, if the selected goal id is not among the active goals, the selection resets to "None", so Create never submits a goal the select does not show. Known and left as is: the Sidebar's optimistic pause label can briefly disagree with the service if a pause is toggled elsewhere at the same moment; the next status poll corrects it.
43. **Pause control lives in the Sidebar's Service block.** It shows Running or Paused and a Pause/Resume button, reusing the Sidebar's busy flag and error line; the state comes from the one status poll `App.tsx` already runs, and a successful toggle updates it immediately. The status bar stays text-only. For users: pausing is one click from every screen.
44. **Goals show their linked tasks.** A goal expands to a read-only list of its linked tasks (title and status) loaded through `goals.get`. The list is not a navigation control: the Tasks view has no selection prop and cross-view navigation was a larger change than this pass justified.
45. **Schedule rows name their goal and times are local.** Rows with a goal show "Goal: <title>" (or "Unknown goal" if it is not in the loaded list). "Next" uses a locale date and time. Schedule preview instants and attempt times still print raw ISO strings; they are not user-facing summaries.
46. **Sidebar fits short windows.** At the 960x620 minimum window the Sidebar scrolls and tightens spacing under 700 px of height, so "Stop service" and the version line stay visible. The Tauri minimum is unchanged.
47. **Deferred, not implemented: session and permanent approval grants.** Only per-call and per-task (single resolved target) approvals exist. Wider grants change what the model can do without asking, so they need an explicit product policy first; the approval engine stays as is.
48. **Deferred, needs your decision: login registration through SMAppService.** Release builds should register the bundled helper with SMAppService (decision 24). Registering a login item changes persistent state on the user's Mac and needs your approval, so only the dev LaunchAgent (`milo service install`, not installed on this Mac) exists. Blocked on your go-ahead, not on code.
49. **Blocked: notarization and Developer ID signing.** No Apple Developer account is available. `package:mac` keeps ad-hoc signing and reports that the build is not notarized.
50. **Deferred: multi-user isolation and per-app attestation.** The service is a single-user local process guarded by a per-start token file (decision 12). Stronger isolation needs a design pass that is outside this roadmap.
51. **Goal pause or archive does not cancel tasks already linked to it.** Pausing or archiving a goal disables its schedules (decision 35) and blocks new links, but queued and running tasks finish. Goals grant no permissions, so the least surprising behaviour is to leave work in progress alone; cancelling is a user action on the Tasks view.
52. **Honesty check limits, kept as is.** `shell_run` counts as "ran" even when the exit status is non-zero, since the claim is that the command ran. The check is English-only and does not compare "I read the file" with `file_read`. Goal titles, descriptions and notes are user-written and injected as written (decision 35); only generated outcome text is flattened to one line.
53. **Verification status.** Automated checks cover the service (97 tests), typecheck, the app build, the Rust bridge tests and the packaged `.app`. The sidecar cannot be checked by searching its binary for strings (the SEA blob is not plain text), so its freshness is checked by rebuilding from source, comparing hashes and passing the authenticated smoke test. A Homebrew Node 25.9 cannot inject the SEA blob; `MILO_SEA_NODE` points the build at the official Node tarball in `milo-service/build/`. Visual checks were run in ADE's browser against the Vite build with Tauri fixtures (`/tmp/milo-shim`), which is not a native window. Native window launch and macOS notification authorization and delivery were NOT verified: the lane's Mac Desktop driver never created a display (`MAC_DESKTOP_NO_DISPLAY`), and launching the app outside it would attach to a running dev service on the default data directory. These need the lane display fixed and an approved OS authorization prompt.
54. **Unmanaged dev service.** A `node` service started from this repo's `service.ts` (pid 73743, before this pass) still runs old code and owns the default data directory. It was not started by this work and was left running; stop it before testing the packaged app.

## Verification audit

- The previous read-only shell shortcut was not a safe authorization boundary: an executable with a trusted basename could run arbitrary code. Every shell invocation now requires approval and records a process effect; an interrupted execution has an uncertain outcome. The granted folder is a working directory, not a filesystem or network sandbox. This supersedes decision 8 and earlier claims that read-only shell commands run without approval.
- A successful file write does not establish that a deletion occurred; the honesty check no longer treats it as evidence of deletion. The check remains heuristic, and the remaining filesystem path race remains documented rather than claimed fixed.
- Pausing or cancelling during inference retry backoff prevents another request. A fatal worker error stops admission and reports the failure instead of automatically restarting queued work.
- Decision 42's silent clearing of an unavailable schedule goal could create an unintended unlinked schedule. The form now retains the selection, warns, and requires an explicit replacement or None. Status polling is serialized and cannot overwrite a newly confirmed pause or resume with an older response; this supersedes the race accepted in decision 42.
