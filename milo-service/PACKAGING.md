# macOS build

The current packaging path produces a locally ad-hoc-signed app for the build machine's architecture. It is not notarized or ready for public distribution; third-party dependency notices and license obligations still need review. It needs Rust, Xcode command-line tools, the app and service npm dependencies, and Node 25.5 or newer that supports `--build-sea`.

From `milo-app`, run `npm run package:mac`. If the installed Node cannot build a SEA (some dynamically linked Homebrew builds omit the required fuse), set `MILO_SEA_NODE` to the absolute path of a suitable official Node binary. Check its version and verify downloads against the publisher's checksums before building. The build includes the selected Node distribution license and the project license; if Node is installed without its license beside the binary, set `MILO_NODE_LICENSE` to its license file. The script refuses mismatched Rust and Node architectures and runs a socket health smoke test on the sidecar before bundling. It signs both the sidecar and the app ad hoc, then verifies the bundle signature.

The app connects to a running service or starts its bundled sidecar. Its Stop button controls only the process the current app instance started; a separately installed login agent must be managed through its own supervisor. Quitting the app does not stop the service. In the packaged app, a signed notification helper runs under the app bundle identity. When enabled by the user, the service can send generic notifications while the app is closed. Actual delivery depends on macOS authorization; the unbundled development service reports this feature unavailable.
